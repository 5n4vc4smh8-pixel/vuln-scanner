### Recomendações priorizadas

- Prioridade 1: corrigir imediatamente as vulnerabilidades críticas correlacionadas — grupos como DireWolf e Devman exploram esse padrão para acesso inicial e exfiltração antes da criptografia.
- Prioridade 2: grupos que já publicaram organizações brasileiras (DireWolf, Devman, Vect) estão ativos. Monitorar os leak sites (Proven Data) e preparar plano de resposta a incidente com foco em dupla extorsão.
- Prioridade 3: verificar no feed CISA KEV se o software exposto possui CVEs com exploração ativa e aplicar patches prioritariamente.
- Prioridade 4: validar controles de exfiltração (DLP), segmentação de rede e backups imutáveis — a criptografia é secundária; o prejuízo real vem do vazamento de dados.

**Nota metodológica:** as publicações de vítimas em leak sites são alegações dos próprios criminosos e não constituem confirmação de incidentes. A base de grupos é atualizada manualmente com base em fontes públicas; em operações de produção, recomenda-se integrar um feed de CTI (MITRE ATT&CK, AlienVault OTX, MISP) para atualização automática.

## Detalhamento das Vulnerabilidades

### 1. Open Redirect (Severidade: Medium)

**ID:** OPEN-001
**CWE:** CWE-601
**URL:** http://127.0.0.1:9999/sair
**Parâmetro:** url
**Descrição:** O parâmetro permite redirecionamento para domínios maliciosos.
**Remediação:** Valide URLs de redirecionamento contra uma whitelist de domínios permitidos.
**Evidência:** `Redirect to: evil.com (body/JSON, sem header Location)`
**Referências:**
  - https://owasp.org/Top10/A01_2021-Broken-Access-Control/
  - https://portswigger.net/web-security/open-redirect
---

### 2. Insecure Direct Object Reference (IDOR) (Severidade: Medium)

**ID:** IDOR-001
**CWE:** CWE-639
**URL:** http://127.0.0.1:9999/buscar
**Parâmetro:** id
**Descrição:** O endpoint devolve recursos diferentes apenas trocando o valor numérico do parâmetro, sem verificação de autorização.
**Remediação:** Valide a autorização do usuário para cada objeto acessado (acesso indireto, ACLs, tokens opacos).
**Evidência:** `id=1 → 143 bytes | id=999999999 → 30 bytes (sem autorizacao)`
**Referências:**
  - https://owasp.org/Top10/A01_2021-Broken-Access-Control/
  - https://portswigger.net/web-security/access-control/idor
---

### 3. Information Disclosure (Severidade: High)

**ID:** INFO-DISC-001
**CWE:** CWE-200
**URL:** http://127.0.0.1:9999/api/debug
**Parâmetro:** response_body
**Descrição:** O endpoint expõe dados sensíveis (usuários, hashes de senha, dados internos de debug) sem autenticação.
**Remediação:** Remova endpoints de debug em produção, autentique as APIs que expõem dados sensíveis e nunca retorne hashes de senha ao cliente.
**Evidência:** `Sensitive data found in response body`
**Referências:**
  - https://owasp.org/Top10/A01_2021-Broken-Access-Control/
  - https://cwe.mitre.org/data/definitions/200.html
---

### 4. Local File Inclusion (LFI) (Severidade: Critical)

**ID:** LFI-001
**CWE:** CWE-22
**URL:** http://127.0.0.1:9999/download
**Parâmetro:** arquivo
**Descrição:** O servidor está incluindo arquivos locais via input do usuário.
**Remediação:** Valide entradas, use whitelist de arquivos permitidos.
**Evidência:** `..&#x2F;..&#x2F;etc&#x2F;passwd`
**Referências:**
  - https://owasp.org/Top10/A03_2021-Injection/
